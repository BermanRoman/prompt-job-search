# Карточка кампании

Скопируй в приватный `runs/<campaign>/campaign.md`; не публикуй реальные резюме, адреса и переписку.

## Профиль и поручение

- ID кампании и путь единственной рабочей БД:
- Цель, роли, уровень, интерес и причина выбора:
- Обязательные условия / предпочтения / неизвестное:
- География, удалённость, занятость, зарплата с валютой и gross/net:
- Дорога: допустимое время в одну сторону, транспорт, пересадки, график и дни присутствия; точка старта для карт и разрешение её использования:
- Срок выхода, допустимые поездки/переезд, ограничения:
- Исключённые компании и область запретов контакта:
- База фактов, версия, SHA и разрешённые к раскрытию поля:
- Уже известные ответы кандидата и их условия:
- Источник прямого поручения, точный текст/снимок и SHA:
- Разрешённые действия: настройка поиска / отклики / email / ответы / напоминание:
- Аккаунты и каналы, без секретов:
- Критерии адресатов и допустимая персонализация:
- Срок действия UTC, максимум всего/день; источник этих пределов:
- Отзыв/изменение поручения и момент применения:
- Что требует решения пользователя:
- Шаг 7 наставника: не предложен / предложен / принят / отклонён; отказ сохраняется:

## Каналы

| Канал | Вкладка и доступная браузерная операция | Проверено когда и чем | Сохранённый поиск/папка/последняя проверка | Ограничения |
|---|---|---|---|---|
| | | | | |

Используется браузерная сессия; в поле проверки не записывай токен или cookie.

Для Checko отдельно укажи приватный каталог кэша, budget ID, предел запросов и согласованный денежный предел/тариф; ключ в карточку не записывается.

## Компании без вакансий

- Волна 1: источники, фильтры, дата и граница текущего пакета; исход каждой записи и оставшиеся блокеры:
- Основание перехода к волне 2, дата; открытые ответы и продолжения первой волны:
- Перед каждым новым предложением: проверка актуальных вакансий и прежних контактов по company/роли/задаче, результат и источник:

Карточки по templates/company.md: ИНН/юрлицо, версия, результаты API → сайт → карты, доказательства рисков, неизвестное, основание предполагаемой задачи и опубликованного делового контакта.

После копирования относительные пути шаблонов разрешай от корня библиотеки.

Различай карточку компании, предполагаемую задачу и подтверждённую вакансию; company opportunity имеет kind=company_proposal и устойчивый ID, общий для To/CC и каналов того же предложения.

До отправки проверяй актуальные отказы по компании, все адреса To/CC, содержание письма/вложений и ограничения раскрытия кандидата.

## Пакеты и проверки

| Opportunity ID | Источники и доказательство идентичности | Версия вакансии | Соответствие/пробелы | ATS и требования файла | База/ATS/human/письмо SHA | Ревью и раунд | Действие |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

Полные снимки вакансий, тексты и файлы лежат локально рядом, журнал хранит версии и ссылки, а не весь контекст.

## Первоначальные отклики

Веди через [локальный журнал](../scripts/README.md), после копирования шаблона путь разрешай относительно корня библиотеки.

Одна БД на кампанию сохраняется при возобновлении и смене policy; новая policy не означает новую кампанию или сброс лимитов.

## Входящие и ответы

| Opportunity / компания | Канал и ID входящего | Суть вопроса | Fact IDs / неизвестное | Адресат и SHA ответа/вложений | Поручение и ревью | Попытка: reserved/unknown/sent/not_sent | Receipt / доказательство | Напоминание использовано |
|---|---|---|---|---|---|---|---|---|
| | | | | | | | | |

До ответа одному входящему назначь одного исполнителя и запиши reserved; unknown запрещает повтор до сверки исходящих, sent требует подтверждения сервиса.

Лимиты первоначальных подач и переписки учитывай раздельно и явно: если пользователь дал общий предел всех сообщений, добавляй ручные ответы к расходу перед новым внешним действием.

Автоматический журнал первой версии не считает эти ручные сообщения и не обеспечивает их блокировку между параллельными процессами; переписку ведёт один исполнитель.

- Следующий шаг и условие возобновления:
